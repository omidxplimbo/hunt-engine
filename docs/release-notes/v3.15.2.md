## Documentation policy

From v3.15.2 onward, every feature added, changed, removed, renamed, moved, or behaviorally modified must update the Documentation Portal, feature inventory, screenshots when UI changes, release notes, and smoke coverage where applicable.

A feature is not release-ready unless documentation is updated, or an explicit roadmap/PDF-approved documentation exception exists.

## Security documentation rule

Security-sensitive and Operator-related documentation must explain:

- scope
- authorization
- policy gates
- approval requirements
- runtime backend
- budget and stop conditions
- audit behavior
- memory behavior
- evidence interpretation
- what is executed
- what is not executed


## Screenshot status

v3.15.2 defines the screenshot convention, required screenshot checklist, screenshot paths, and Documentation Portal screenshot slots.

Actual screenshot capture is intentionally deferred to a follow-up documentation-content pass because manual capture/upload is time-consuming. This is not an exception to the long-term documentation rule: future UI changes must update screenshots when relevant.

Required screenshot paths remain tracked in:

- `docs/documentation/screenshot-checklist.md`
- `frontend/public/docs/screenshots/fa/`
- `frontend/public/docs/screenshots/en/`

## Validation

The documentation route smoke verifies that `/documentation` returns the React shell and that the frontend bundle contains documentation portal markers.

## Notes

v3.15.2 is a documentation foundation milestone. It does not replace the existing v3.16+ roadmap. It adds the product documentation requirement that future feature work must satisfy.
