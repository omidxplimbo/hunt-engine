# Hunt Engine v3.14.0 — Pentest Skill Registry + Operator Skill Runtime Foundation

v3.14.0 advances Hunt Engine from a single-path AI hunting loop toward a modular AI pentest operator built around Skills, Agents, Memory, Observations, and policy-aware runtime dispatch.

This release adds the Operator Skill Registry, evidence-aware skill selection, planned skill runs, skill observations, target memory ingestion, enriched skill run APIs, chat-visible execution summaries, and the first set of inventory/planning runtimes for authorized vulnerability validation workflows.

v3.14.0 is not a full exploit runtime release. It establishes the professional operator foundation for later controlled validation and authorized exploitation workflows. Planning runtimes do not execute payloads; they identify candidates, preserve evidence, update target memory, and prepare controlled next actions.

## Skill runtimes

### Parameter Inventory

The `parameter_inventory` runtime reads existing target URL inventory, extracts query parameters, maps them to candidate bug classes, creates candidate observations, and persists parameter notes to target memory.

### HTTP Evidence Analysis

The `http_evidence_analysis` runtime reads controlled runtime HTTP results, classifies completed/blocked/inconclusive evidence, creates observations, and persists HTTP evidence analysis to target memory.

### Auth Context Needed

The `auth_context_needed` runtime records the authenticated context required before meaningful IDOR/BOLA/BFLA/API authorization/session/business-logic validation. It creates a `needs_context` run, a `next_step` observation, and policy-context memory.

### JS Audit

The `js_audit` runtime reviews existing URL inventory for JavaScript assets, source map candidates, API-like routes, and frontend routes. It is inventory-only in v3.14.0 and does not perform new crawling.

### XSS Reflection Planning

The `xss_reflection` runtime identifies XSS/reflection-relevant parameters from parameter inventory observations and found URLs. It creates candidate or learning observations and vulnerability hypothesis memory.

Runtime scope: `planning_only_no_payload_execution`.

### Open Redirect Planning

The `open_redirect` runtime identifies redirect/url-like parameters such as `redirect`, `next`, `url`, `callback`, and `return`. It creates candidate or learning observations and vulnerability hypothesis memory.

Runtime scope: `planning_only_no_redirect_validation`.

### Path Traversal Baseline Planning

The `path_traversal_baseline` runtime identifies file/path/download/template/include candidates. It creates candidate or learning observations and vulnerability hypothesis memory.

Runtime scope: `planning_only_no_file_read_validation`.

## Guardrails and execution model

v3.14.0 keeps real validation and exploitation workflows controlled, authorized, scope-aware, rate-limited, audited, and policy-gated.

Planning runtimes do not execute payloads or claim impact. They prepare evidence-driven next actions for controlled runtime expansion and later authorized validation workflows.
