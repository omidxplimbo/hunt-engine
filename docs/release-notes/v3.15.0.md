# Hunt Engine v3.15.0 — User-Programmable Operator Skills + Personal Operator Learning

v3.15.0 extends Hunt Engine from a built-in skill registry into a user-programmable AI pentest operator foundation.

This release adds Operator Methodology / Skill Instruction records, target-level methodology selection, methodology injection into the operator planning prompt, user-defined executable skill CRUD, a full Executable Skills management UI, target-profile visibility for custom skills, custom skill trigger matching in Attack Surface Chat, planned OperatorSkillRun creation for matching custom skills, and chat-visible dispatcher-gated custom skill queues.

v3.15.0 does not yet execute arbitrary user-defined custom runtimes. It prepares the authorized execution foundation by making custom skills plannable, selectable, auditable, target-scoped, and visible in the operator workflow. Runtime execution remains dispatcher-gated until later runtime patches add explicit execution backends, permission modes, budgets, stop conditions, and policy enforcement for custom workflows.

## Operator Methodology / Skill Instructions

OperatorLearningRecord entries are user-authored methodology, notes, and workflow instructions. They are not executable skills by themselves.

Target-selected methodology records are used as planning guidance when their skill_slug, bug_class, or workflow context matches selected operator skills. The operator prompt treats methodology records as guidance, not vulnerability evidence.

## User-defined Executable Skills

OperatorSkill now supports user-defined skill records with scope, origin, skill_type, runtime_backend, permission_mode, trigger_signals, custom_definition, budget_defaults, stop_conditions, authorization requirements, and default risk/safety/test/autonomy levels.

User-defined skills can be created, edited, deleted, enabled, disabled, listed, and selected by the chat planning layer. Built-in skills remain read-only.

## Chat planning integration

When an operator chat message has high-impact, reportable, or class-specific pentest intent, the selector now considers user-owned enabled custom skills.

A custom skill can be selected when slug, name, category, bug_class, skill_type, runtime_backend, trigger_signals, built-in class signals, or high-impact/reportable intent match.

Selected custom skills are added to selected_skills, recorded in assistant output_json, and queued as planned OperatorSkillRun rows.

## Runtime behavior

Custom skill runtime execution is not wired in v3.15.0.

When a custom skill is selected, the dispatcher keeps it in the queue as status=planned, skill_execution.not_implemented, a planned OperatorSkillRun, and a visible User-defined Skill Queue block in chat.

This preserves the professional execution boundary: user-defined skill runtime execution must be introduced through explicit runtime patches with scope, policy, permission mode, budgets, stop conditions, audit trail, and approval controls.
